# The iPhone app, v1.1

2026-10-05. Status: built; awaiting the tester. Follows `2026-10-05-mobile-app-design.md` (v1).

## What it is

Five things the web app can do and the phone app cannot yet, in this order:

1. start a new session from the phone (a project, or resume a recent Claude conversation);
2. the slash-command menu when the message starts with `/` (and `@` for files, which comes with it);
3. pictures: photo library or camera, sent the way the web sends them;
4. voice: hold to talk, the words go out or into the composer;
5. the terminal screen of a session, at any time, not only from a card.

No server change is needed for any of them. Every endpoint below already exists and the web uses it.

## Invariants

1. **One rule, one place.** What decides something — which recents are folded, when a resume needs a
   warning, how a hold turns into a message, how a picture is named in the text — lives in `libs/client`
   and the web and the phone both call it. The apps only draw and wire platform parts in.
2. **A message is what the user saw in the composer when they sent it.** Pictures still uploading are not
   in it; a voice hold that was cancelled is not in it; nothing arrives later and gets appended.
3. **Nothing the phone does creates a second Claude on one conversation.** A recent conversation that is
   already open goes to that session; one a background session holds cannot be resumed; one active in the
   last 2 minutes asks first.
4. **Listening stops when the screen it belongs to is gone.** No microphone left on after a back swipe,
   the app going to the background, or the session ending.
5. **Every word on screen is in `@workoffdesk/i18n`, en and zh.**

## Who already knows each fact

| Fact | Who knows it | So |
| --- | --- | --- |
| Which projects exist | `GET /api/claude/projects` | list it, no local copy |
| Recent conversations, open where, held by background, automated | `GET /api/claude/recent` (`openIn`, `background`, `automated`, `lastActivity`) | decide from these fields only |
| A new session's id | the `POST /api/m/local/sessions` answer | navigate by it, do not wait for the list push |
| Slash commands of a session | `GET .../sessions/:id/commands` (empty for a shell) | load once per session, on the first `/` |
| Files for `@` | `GET .../sessions/:id/files` | kept 30 s, as the web does |
| What a picture is (png/jpg/gif/webp/heic) and its size limit (30 MB) | the server reads the bytes in `POST /api/uploads` | the phone sends bytes as `application/octet-stream`; no type sniffing or HEIC conversion on the phone |
| Whether the user allowed camera / mic / speech | iOS, via the permission result | ask at the moment of use, show the denial in words |
| Whether recognition has ended | the recognizer's `end` event | the hold machine waits on it, bounded by FINISH_MS |
| Whether the session screen is in front | expo-router focus (`useIsFocused` / `useFocusEffect`) and `AppState` | stop listening and polling from these, not from our own flags |
| What the terminal shows | `GET .../sessions/:id/screen` (plain text) | poll it while the sheet is open and the app is active |

## Which layer

New or moved in `libs/client` (platform-free, React-free, tested later by the tester like the rest of the lib):

- `newSession.ts`
  - `createSession(api, spec): Promise<TermSession>` — the POST; callers navigate.
  - `recentFound(all, query): { people, programs }` — the filter (has `cwd`, matches title/path) and the
    split the web did inline.
  - `canPickUp(r)`, `LIVE_MS`, `maybeOpenOnMac(r, now)` — the rules in invariant 3.
  - The web's `NewSessionSheet` and `ClaudeView` use these (same behaviour, less code there).
- `slash.ts` gets `withMention(text, caret, mention, path)` — the text and caret once a picked file
  replaces the `@` being typed, before inside the web Composer's `name()`.
- `images.ts` gets `withPictures(pictures, text)` — the one place a message with pictures is put together
  (web Composer and phone Composer, typed or spoken).
- `talk.ts` — the hold machine that was the web Composer's `startHold`, lifted out unchanged in behaviour:
  `startTalk(recognize, { show, write, send, failed, say })` returns `{ move(zone), release(zone), drop() }`
  (or null when the recognizer could not start), with `FINISH_MS`, the `no-speech`/`aborted` ignore rule
  and `notHeard` / `micJustOn`. `failed(error)` hands the recognizer's own error name to the app, which
  words it for its platform (a home-screen web app and the iPhone app are refused for different reasons).
  The recognizer is injected: `(onText, onEnd, onStart) => { stop, abort }` — the shape of the web's
  `startLiveSpeech`, so the web passes that and the phone passes an adapter. The web Composer keeps its
  pointer handling and drawing; only the machine moved.

Mobile only (`apps/mobile/src`): the screens, the picker and recognizer adapters, gestures.

Not moved, noted for later: snippets (`workoffdesk.snippets` in localStorage) would need a
`createSnippets(storage)`; the phone has no snippet editor, so the phone's slash menu shows commands only.

## 1. New session

- List screen header: a `plus` SymbolView button, left of settings. Opens `new-session` as a modal route
  (`presentation: 'formSheet'` / pageSheet) with three steps in one screen, like the web sheet: menu →
  projects (optional name, a custom path field) → recent (search, automated folded unless searching,
  `alreadyOpen` / `inBackground` chips, background-held rows disabled unless `openIn`).
- Pick a project → `createSession` → close the modal, `router.push('/session/<id>')`.
- Pick a recent:
  - `openIn` set → go to that session.
  - otherwise → `claude/[sid]`, a new read-only route: the transcript from
    `useChat(sid, '/api/claude/sessions/<sid>/chat')` drawn with the existing `Turn` components, a
    `readOnly` chip, and a "Continue on phone" button → if `needsWarning`, show `maybeOpenOnMac` and ask a
    second tap; then `createSession({ resumeId, title, cwd })` → `router.replace('/session/<id>')`.
- Empty list: a line pointing at the new button (`noSessionsPhone`; the web's `noSessionsSub` offers a
  Shell too, which the phone does not).

Breaking paths and what each does:

| Path | Result |
| --- | --- |
| Double tap on a project / Continue | `busy` disables every option until the request settles; failure re-enables and shows `openFailed` |
| New session id not yet in the session list | the session route already renders from its id; title fills in when the list push arrives |
| 409 `background-session` on resume | the server's message shown, nothing navigates |
| Project list or recent list fails | error line in the sheet; going back to the menu and in again refetches |
| Custom path that does not exist | the server's error shown, user can edit the path |
| Modal swiped down mid-request | the request finishes, no navigation after unmount (focus check) |

## 2. Slash menu (and `@` files)

- In the phone Composer: `slashQuery(text)` non-null → a list above the composer (inside the keyboard
  avoiding view), `matchCommands(commands, q)` rows with `describe(c)` as the subtitle. Tap → the text
  becomes `/<name> `, cursor at the end.
- Commands load on the first `/` in this session (`commands` prop, a function, as the web's `loadCommands`).
  A failed load leaves `null` so the next `/` retries; a shell answers `[]` and the menu does not open.
- `@`: `mentionAt(text, cursor)` → `matchFiles(files, q)` (first 30); tap replaces the `@query` with
  `withMention(...)`. Needs the cursor, so the TextInput reports `onSelectionChange`.
- Breaking paths: typing fast past the load (the menu filters whatever is loaded when it arrives); `/` in
  the middle of a message (`slashQuery` only matches at the start, as on the web); the menu covering the
  last chat lines (it is capped to about 5 rows and scrolls).

## 3. Pictures

- New dependency: `expo-image-picker` `~57.0.20` (SDK 57).
- Composer gets a `photo` button left of the input → an ActionSheetIOS:
  `t.photoLibrary` / `t.takePhoto` / cancel.
  - Library: `launchImageLibraryAsync({ mediaTypes: ['images'], allowsMultipleSelection: true,
    selectionLimit: 6, quality: 0.8 })`. iOS uses PHPicker: no photo permission needed.
  - Camera: `requestCameraPermissionsAsync()` first; denied → `t.cameraDenied` with an "Open Settings"
    action (`Linking.openSettings()`); then `launchCameraAsync({ quality: 0.8 })`.
- Each asset: `const body = await (await fetch(asset.uri)).blob()` → `api('/api/uploads', { method:
  'POST', body, headers: { 'content-type': 'application/octet-stream' } })` → `{ path }`. The bearer
  header comes from the lib `api` as for every request.
- Pictures show as thumbnails in a row above the input, drawn from the phone's own file (no round trip),
  each with a remove `xmark`. While any is uploading, Send is disabled and a spinner sits on that
  thumbnail. Send → `withPictures(pictures, text)`; on success the pictures clear, on "not connected" they
  stay with the text (as the web).
- Breaking paths: picker cancelled (`canceled: true` → nothing); one of several uploads fails
  (`uploadFailed` on that thumbnail, it is dropped, the rest stay); over 30 MB or not a picture (the
  server's 413/415 message); leaving the screen mid-upload (result ignored after unmount; the file on the
  server is harmless, it is only referenced if sent); HEIC from the camera roll (server converts);
  sending with only pictures and no text (allowed, as the web).
- Risk to check at the end: RN `fetch(file://).blob()` as a request body. If the bytes do not arrive
  intact, the fallback is `expo-file-system`'s `File(uri)` (`~57`, already a transitive dep of expo)
  passed as the body.

## 4. Voice

- New dependency: `expo-speech-recognition` `57.1.0` (versioned with SDK 57; peers `expo`, `react`,
  `react-native` any). Its API mirrors Web Speech, so the adapter is short:
  `start({ lang, interimResults: true, continuous: true, addsPunctuation: true })`,
  `result` → `onText(transcript)`, `start` → `onStart`, `end` → `onEnd()`, an error other than
  `no-speech` → `onEnd(error)` at once (iOS sends no `end` after some start failures), `stop()` / `abort()`.
  `lang` is language-region from `expo-localization` (`zh-CN`), which is how Apple's recognizer names
  them; iOS's own tag (`zh-Hans-CN`) is not one it takes. Events go through `ExpoSpeechRecognitionModule.addListener` inside the adapter
  (not the hook), so the adapter is a plain function the lib machine can call.
- Gesture: a `mic` button in the composer when the text is empty and nothing is uploading. Press and
  hold for HOLD_MS (300) → the hold machine starts; a tap says `t.holdToTalk`. Starting asks for the
  microphone and recognition itself (the module's `start` requests both): the first time iOS shows its
  dialogs, the finger comes up on them, and that case gives `t.micJustOn`, as on the web.
  A panel over the composer shows what is heard and three targets: send (default), cancel (slide up-left),
  to text (slide up-right), the same targets as the web `VoicePanel`, drawn natively. Built on RN
  `Pressable` + `onResponderMove` coordinates measured against the targets' `measureInWindow`; no gesture
  library needed.
- Release → `talk.release(zone)`; responder terminated (a system alert, a call) → `talk.drop()`.
- Invariant 4: `useFocusEffect` cleanup and an `AppState` change to `background` call `talk.drop()`;
  the session ending (exit push) does too.
- `not-allowed` → `t.speechDeniedApp` with "Open Settings"; `service-not-allowed` (iOS: the recognizer
  is unavailable, which can pass, such as offline) → `t.speechOff`, and the mic stays; anything else →
  `t.speechStopped(error)`.
- The keyboard's own dictation key keeps working with no code; this feature is the hold-to-send one.

## 5. Terminal screen

- The mobile `ScreenSheet` (in `Footer.tsx`) exists; today it opens only from a card, the waiting bar or the
  shell overlay. Add a `terminal` SymbolView button to the session header so it opens at any time.
- While the sheet is open, the app is active and the screen is focused, it refreshes every 2 s (the socket
  carries no terminal output, so polling is the only source); manual refresh stays. Stopped by the
  sheet closing or `AppState` leaving `active`.
- The `KeyBar` (arrows, esc, tab, ctrl-c, ⏎) sits under the text in the sheet, so a stuck prompt can be
  answered while watching it; after a key the sheet refreshes once at once.
- Monospace, horizontal scroll for long lines, scrolled to the bottom on open.
- The server answers plain text; colours would need the server to send the ANSI screen (a change in
  `apps/server`, so the lead's). Out of scope for v1.1, noted.

## app.json changes (for the lead to apply)

Add to `expo.plugins`:

```json
[
  "expo-image-picker",
  {
    "photosPermission": false,
    "cameraPermission": "WorkOffDesk uses the camera to take a picture and send it to your session.",
    "microphonePermission": "WorkOffDesk uses the microphone while you hold to talk, to turn what you say into a message."
  }
],
[
  "expo-speech-recognition",
  {
    "microphonePermission": "WorkOffDesk uses the microphone while you hold to talk, to turn what you say into a message.",
    "speechRecognitionPermission": "WorkOffDesk turns what you say into text for your message while you hold to talk."
  }
]
```

- `photosPermission: false`: the library picker is PHPicker and needs no `NSPhotoLibraryUsageDescription`;
  leaving the key out avoids a permission string App Review asks about.
- The image picker gets the same microphone string as the speech plugin: `false` there deletes
  `NSMicrophoneUsageDescription` whichever plugin runs last, and drops `RECORD_AUDIO` on Android.
- Chinese permission strings: iOS shows `InfoPlist.strings` per language. With `expo-localization`
  `supportedLocales` already set, add `expo.locales`:
  `"locales": { "zh-Hans": "./locales/zh-Hans.json" }` and a file `apps/mobile/locales/zh-Hans.json`:

  ```json
  {
    "NSCameraUsageDescription": "WorkOffDesk 用相机拍照，发送到你的会话。",
    "NSMicrophoneUsageDescription": "按住说话时，WorkOffDesk 用麦克风把你说的话变成消息。",
    "NSSpeechRecognitionUsageDescription": "按住说话时，WorkOffDesk 把你说的话转成消息文字。"
  }
  ```

  (I can write that json file if you want it; it is outside `src`, but it changes the build, so it is yours to
  say.)
- Both packages are native: the next build needs `expo prebuild` + pod install, which your release script
  already does with `--clean`.
